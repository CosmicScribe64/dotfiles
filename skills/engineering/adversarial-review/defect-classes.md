# Defect classes

Give every class a verdict in the report. After the first instance of a class, find all its siblings before moving on. A verdict line that describes a defect is a finding: report it, at least as Minor.

- **Reset on re-entry**: list every field of the state a switch, reload, reopen or retry touches (selection, cursor, time, cache, overlay, error), including closure and module-level variables, and name the entry point that resets each. Check each field is reset on every such path, not just the field that surfaced. Check every event that changes an input of a derived output (draw, summary, index) triggers a recompute.
- **Construction vs config order**: values read in a constructor or initialiser before config, overrides or startup state are applied. Follow a nondefault seeded value all the way to the component that uses it.
- **Other writers**: a field the change now sets that older code also sets or patches, including explicit `false`, `0` or empty values that a later default overwrites. A later unconditional write over a seeded or user-set value is a finding unless the requirement says the later write wins; test with the seed set opposite to the patch.
- **Boundary values**: `null`, NaN, infinity, empty string, empty list, missing key and zero crossing a serialiser, an API, a language boundary or a mode switch. Run each value through the reader and check what it does, not what the writer intended; reasoning that it is safe is not a verdict.
- **Precision and transforms**: int64 ids and nanosecond times through doubles, JSON or JS `Number` (exact only to 2^53); rounding or truncation before a comparison or window check; timestamps an encoder, re-mux or resampler rewrites. Run the value through the real transform (the real tool, at the version CI uses) and compare it after, not before.
- **Interval endpoints**: for every pair of functions that bucket, window or range-check the same quantity, name each one's inclusive/exclusive rule and show they agree. Test a value exactly on each edge.
- **Fallback lookups**: nearest, predecessor, closest, `bisect`, "last at or before" and default-on-miss lookups. Build inputs where the exact key is missing, duplicated or null and show what is returned; a neighbour returned silently in place of a miss is a finding.
- **Partial I/O**: every read from a subprocess, pipe, socket or remote shell. Try a short read, a missing or vanished file, a nonzero exit, EOF that never arrives and a hung peer; check a timeout bounds every read, not just the connect, and that failure leaves no false result.
- **Filesystem safety**: paths built from input or listings. Check containment after resolving symlinks and `..`, exclusive creation of temp and output files, file modes, and cleanup on every exit path.
- **Producer formats**: every filename, suffix, encoding, unit and version the real producer can emit, read from the producer's code rather than sample data (collision suffixes, rotated or recovered files, legacy versions).
- **Multi-source input**: duplicate, overlapping or interleaved inputs; a second tenant, vehicle, user or run in the same folder or stream; inputs the change's own code lists together. Check every aggregation (latest, merge, dedupe, max). For each output field taken from input, name the filter that ties it to the right entity; a guard on a different field does not count.
- **Ties and equal keys**: sorts, dedupe, "latest wins" and selection with equal keys. Stable sorts keep input order, which may be the wrong winner. For each composite identity key, name the producer of each component and show the key is unique across every source that shares the container. List every map, set, object or join keyed by an id in the changed code and its consumers, and give each its own verdict line with an input where two sources share the id.
- **N of 3 or more**: loops that merge, replace a winner or chain. Run three or more inputs and check any recorded id or count against the final state, not the state at record time.
- **Lists of kinds**: when the change adds a topic, message type, enum value, mode or file kind, find every allowlist, switch, filter, registry and test fixture that enumerates the existing kinds, and check each includes or deliberately excludes the new one.
- **Non-final states**: an outcome counted, labelled or dropped while a later stage can still change it (a rejection later recovered, a pending item later matched). Follow each item to its last state before checking what is reported for it.
- **Heuristic predicates**: for each heuristic, build a counterexample, and check its inputs still carry the needed information after earlier transforms (clipping, rounding, filtering). For an equality or threshold that classifies inputs, build two inputs that are equal after the transform but different before. A killed mutant shows the branch is tested, not that it is right. A guard that raises or skips on a heuristic is a classifier too: build a valid input it rejects. Blocking real input is a finding. Give every comparison that decides identity, duplication, nesting or ordering its own verdict line, including comparisons inside raise, warn or skip branches, each with an input where only the compared key is equal.
- **Derived caches**: when a decoder's or generator's output shape or meaning changes, find caches, version constants, snapshots, golden files and fixtures derived from it and check each is bumped or regenerated.
- **False status**: summaries, states, logs and return codes claiming applied, done or success on an empty, skipped or failed result. Check each status field against every path that sets it.
- **Tests that cannot fail**: tests never collected or run (a script with no test calls, a wrong name pattern, a skipped target), and assertions that pass with the code broken. Break the code and watch for red.
- **Every mode**: a feature's headline behaviour checked in each mode it claims (live vs replay, online vs offline, each platform), measured on real data where possible. Fill the report's Modes table: each field the consumer reads, per mode, with the producer that sets it; a field set in only one mode is a finding.
- **Consistent snapshots**: two values picked by time from separately timed streams and then joined by id. Check the id resolves in the picked snapshot, and what is drawn or counted when it does not.
- **Platform behaviour**: native features of the elements and runtimes used (fullscreen, picture-in-picture, resize, zoom, keyboard focus), working directory and environment under the launcher (`bazel run` starts in runfiles; the caller's directory is `BUILD_WORKING_DIRECTORY`), file permissions, and time zones. External tools at the versions CI and the target run, not the local ones: flags and output fields can differ (for example ffmpeg 4.4 has no `-fps_mode` and no ffprobe frame `pts`).
- **Stale prose**: docs, READMEs, comments and help text that still describe behaviour the change or a later fix replaced, or that contradict the code they sit on (numbers, units, directions, formulas).
- **Standing requirements**: requirement and architecture documents in each touched project directory. A change that contradicts one is a finding even when the plan asks for it.
- **Stated standards**: changed lines checked only against rules written in the repo's tracked standards files (for example CODING_STANDARDS.md, CONTRIBUTING.md, AGENTS.md, style guides), plus missing includes or imports a strict build would reject. Report each as a Nit citing the rule. Nothing else about style.
